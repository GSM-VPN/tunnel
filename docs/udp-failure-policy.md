# UDP 전송 장애 처리 정책

UDP는 전달·순서·중복 제거를 보장하지 않는다. Tunnel은 UDP 위에 TCP식
재전송 계층을 추가하지 않고, 세션 상태 전이와 암호화 경계를 통해 장애를
처리한다.

## 데이터그램별 처리

- 손실된 데이터그램은 조용히 복구하지 않는다. Keepalive와 유휴 타임아웃은
  세션을 제한된 재연결 경로로 전환한다.
- 중복 데이터그램은 세션 키 세대별 Replay Window에서 거부한다. 거부된
  패킷은 장치에 쓰지 않고 Replay 상태도 추가로 소비하지 않는다.
- 재정렬된 데이터그램은 창 안에 있고 인증에 성공하면 허용한다. 이미 처리된
  sequence나 창 밖의 오래된 sequence는 거부한다.
- 예상하지 않은 Endpoint와 잘못된 패킷은 수신 루프를 종료하지 않고 해당
  입력만 폐기한다.

## 세션 및 서버 재시작

일시적인 송수신 오류는 현재 호출의 오류로 반환하고 세션 계층이 Keepalive,
유휴 타임아웃, 제한된 지수 백오프를 적용한다. 재연결은 최대 10회, 1초부터
60초까지의 백오프를 사용하며 무한 재시도하지 않는다.

서버 프로세스가 재시작되면 이전 세션의 데이터 키, Replay Window, sequence
counter를 복원하지 않는다. Established 세션에 `ServerRestarted` 이벤트를
전달하면 세션은 1초 backoff의 `Reconnecting`으로 전환되고, 다음 시도는
새 Noise 핸드셰이크에서 시작한다. Controller는 승인된 피어와 네트워크
정책만 Core에 다시 동기화하고, 새 세션이 인증되기 전에는 이전 데이터
키나 카운터를 재사용하지 않는다.

`ServerShutdown`은 명시적인 영구 종료이므로 `Closing`으로 전환한다. 서버가
실제로 다시 올라왔는지는 플랫폼 Controller가 확인하며, 세션 상태 머신은
프로세스 생존 여부를 추측하지 않는다.

읽기·쓰기 큐 크기와 네트워크 인터페이스 변경에 대한 OS별 정책은 실제
Linux namespace 및 부하 실험이 끝날 때까지 별도 검증 항목으로 남긴다.
